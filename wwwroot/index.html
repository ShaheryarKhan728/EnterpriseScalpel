Trace Matrix

Code Traceability & Impact Analysis

Point it at any Git repo. Get a full requirement traceability matrix. Works with Jira, ClickUp, and Azure DevOps. C# codebases only.

Free and open source. You can run it locally on your system.

How it works

  1. Tag your commits

    Include the requirement ID in each commit message, e.g. REQ-123 Add refund flow.

  2. Point it at your repositories

    Add one or more Git repository URLs, across all the services that make up your product.

  3. Get your traceability matrix

    See every file and method each requirement changed, which files are shared between requirements, and links to each task in your PM tool.

Why Choose Trace Matrix?

Bridge the gap between code and business requirements. Empower your teams with complete visibility into change impact.

🎯
Change Impact & Regression Scope
The Challenge:
Before changing shared code, nobody knows which other features depend on it, so testing is guesswork.
The Solution:
See every requirement that has touched the file or method you're changing, and get a concrete list of business requirements to retest before release.
🏗️
Microservices Architecture Visibility
The Challenge:
No direct references between change requests and implementation across microservices, resulting in vague testing scopes and deployment risks.
The Solution:
Analyze all your service repositories together and see exactly which services each change request touched, so testing and deployment cover the right services.
📊
Business Operation Tracking
The Challenge:
Finding what actual business operations use changed code requires deep domain knowledge and manual investigation.
The Solution:
Connect every code change to its business operations automatically, providing QA and stakeholders with deterministic testing scopes.
🔗
Building on Earlier Requirements
The Challenge:
When developing features on top of previous change requests, manual code review is required for impact determination and timeline estimation.
The Solution:
See which files and methods your new feature shares with earlier requirements, so you can review and estimate the overlap upfront instead of discovering it in testing.
♻️
Refactoring & Technical Debt
The Challenge:
Refactoring and technical debt reduction efforts can identify breaking changes, but testing scope remains uncertain and driven by guesswork.
The Solution:
Find every requirement that touched the code you're refactoring, and use hotspot analysis to choose what to refactor first and exactly what to retest.
🛡️
Audit & Compliance Traceability
The Challenge:
Audits require proof that every requirement can be traced to the code that implements it, and building that matrix by hand takes weeks.
The Solution:
Produce a current requirement-to-code traceability matrix straight from your Git history, and export it as HTML, JSON or CSV whenever an auditor asks.
